# 故障排查

## AE 中没有出现样板

检查：

1. 链接器是否有频道、能量并属于预期 Grid。
2. 目标区块是否加载、方块实体是否仍与指纹一致。
3. 是否命中机器适配器，适配器扫描到多少条/过滤多少条。
4. RecipeManager 代数是否在 `/reload` 后更新。
5. 是否达到每绑定样板上限或过滤配置。
6. 是否调用 `ICraftingProvider.requestUpdate`。

## JEI 有配方但 AE 没有

这不一定是错误。JEI 可能展示不可自动化、概率、环境或客户端伪配方。查看过滤原因；只有适配器能完整表达输入、确定输出和投料语义时才发布。

## AE 显示可合成但投料失败

- 机器忙碌或输入槽被外部物流占用。
- 侧面配置变化，适配器无法插入。
- 模拟与提交之间出现竞态。
- 目录已过期但 provider 尚未刷新。
- 输入的组件/NBT 与具体化样板不一致。

拒绝必须返回 `false` 且零修改。若出现部分投料，视为高优先级数据安全 bug。

## 专服启动崩溃

优先搜索 `NoClassDefFoundError`/`ClassNotFoundException`：公共服务端类可能引用 JEI、渲染或可选 Mek 类。把 compat/client 类物理隔离，并避免它们出现在公共字段和方法签名。

## `/reload` 后重复或旧样板

检查旧代缓存是否清除、指纹 schema、稳定排序、目录原子替换和 `requestUpdate` 次数。不要在玩家登录时用全局清缓存掩盖问题。

## 性能高

使用 `/aeallpattern perf`（实现后）和 spark：比较绑定数量、配方总数、目录重建次数、输入缓存命中和每 tick 扫描。若空闲机器仍反复访问 RecipeManager，先修生命周期，不用单纯增加缓存掩盖。
