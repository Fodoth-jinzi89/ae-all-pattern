# 愿景、范围与术语

## 一句话愿景

把“给一台机器制作几十到几千张 AE 处理样板”变成“绑定一次，自动公开它能稳定自动化的全部配方”。

## 第一阶段 MVP

- Minecraft 1.21.1 + NeoForge。
- AE2 为必需依赖，JEI 与 Mekanism 为可选依赖。
- 一个“全样板链接器”方块，拥有自己的 AE Grid Node。
- 一个两阶段绑定器：先绑定链接器，再绑定机器。
- 原版熔炉适配器。
- Mekanism 电力熔炉适配器。
- 确定性的物品输入、物品输出处理配方。
- AE 终端中出现虚拟可合成项目，不制造实体编码样板。
- 绑定机器显示紫色 AE 风格包围框。
- 重启、区块卸载和 `/reload` 后可恢复。

## 后续范围

- Mekanism 粉碎、富集、锯木、灌注等适配器。
- 多输入、多输出、流体、气体与化学品。
- 概率产物的策略选择。
- 机器白名单、黑名单与每个绑定的样板过滤。
- 跨维度链接、远程区块策略和高级监控 UI。

## 非目标

- 不从 JEI 客户端分类直接驱动专用服务器自动合成。
- 不承诺任意模组机器零配置兼容。
- 不强加载目标区块。
- 不绕过 AE2 安全终端、频道、能量与合成 CPU 规则。
- 不复制、反编译后粘贴或重新发布 AE2、JEI、Mekanism 的代码和素材。
- 第一版不处理结果依赖 NBT、随机状态或世界环境的动态配方。

## 术语

| 术语 | 含义 |
| --- | --- |
| 链接器 | 本模组拥有的 AE 网络锚点与虚拟样板提供者 |
| 绑定器 | 玩家进行两阶段绑定的工具 |
| 目标机器 | 被链接器公开配方并接受 AE 投料的机器 |
| 虚拟样板 | 只存在于内存和 AE 合成服务中的处理样板描述 |
| 机器适配器 | 描述某类机器配方、槽位、投料和产出规则的扩展单元 |
| 配方指纹 | 跨重载稳定识别一条虚拟样板的规范化哈希 |
| 配方目录 | 针对 RecipeManager 生命周期构建的不可变可用配方快照 |
